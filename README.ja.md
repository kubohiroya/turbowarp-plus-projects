# turbowarp-plus-projects

[English](README.md) | 日本語

[TurboWarp Plus Editor](https://kubohiroya.github.io/turbowarp-plus-editor/) で作った作品の、既定の住所を受け持つリポジトリです。GitHub Pages で `https://kubohiroya.github.io/turbowarp-plus-projects/` として配信します。

今はまだ作品を置いていません。このリポジトリは、住所の名前空間を先に確保するためにあります。

## なぜ必要か

TurboWarp Plus の作品は、指紋（内容のハッシュ）ではなく URI で同定します。この URI は SB3 の中のマニフェスト（`turboWarpPlus.uri`）に入ります。URI は作品をダウンロードできる住所であると同時に、その作品の名前でもあります。ブラウザーの拡張キャッシュも、開く人が拡張の許可について選んだ記録も、この名前の下に綴じられます。内容のハッシュは保存するたびに変わります。それを使うと、同じ作品を触るたびに別の作品として綴じてしまいます。

作者が住所を名乗っていない作品にも、エディターは最初の保存で住所を付けます。

```text
<エディターの配信元>/turbowarp-plus-projects/{uuidの末尾2文字}/{uuidの末尾4文字}/{uuid}.sb3
```

- **配信元**は、エディターを開いたページの `location.origin` です。パスは含みません。公開版の Plus Editor は `https://kubohiroya.github.io` から配信されます。そのため、そこで作った作品の住所は `https://kubohiroya.github.io/turbowarp-plus-projects/…` となり、このリポジトリの GitHub Pages を指します。
- **uuid** は UUID version 7 です。初回保存の時刻順に並びます。
- **2段のディレクトリ**は UUID の末尾から取ります。version 7 の先頭はミリ秒時計の上位で、ほとんど変わりません。先頭で分けると、全作品が1つのディレクトリに入ってしまいます。
- 住所はわざと読めない形にしています。タイトルから作った住所は、タイトルを変えると変わります。そうなると、1つの作品が2つ目の名前で綴じられてしまいます。読みやすい住所は「公開する」という意図的な操作で作者が名乗るものです。

例:

```text
https://kubohiroya.github.io/turbowarp-plus-projects/66/66aa/0193f0a1-2b3c-7d4e-8f01-2233445566aa.sb3
```

住所の組み立ては [turbowarp-extension-loader](https://github.com/kubohiroya/turbowarp-extension-loader) の `./project-authoring`（`createProjectUUID`・`defaultProjectURI`）が持っています。エディターへの配線は [turbowarp-plus-editor#55](https://github.com/kubohiroya/turbowarp-plus-editor/issues/55) で行いました。設計の全体は [エディターの構成](https://github.com/kubohiroya/turbowarp-plus-packages/blob/main/docs/editor-architecture.ja.md) の「作品を同定するもの」にあります。

住所の下に何も置かれていなくても、住所はすでに名前として働いています。このリポジトリが無いと、公開版のエディターが付けたすべての住所が「誰のものでもない場所」を指すことになります。

## 決まっていること

- **住所が解決しないことは何も意味しない。** 保存したが公開していない作品と、公開したが住所が消えた作品は、外からはまったく同じ 404 に見えます。到達できるかどうかを根拠に何かを決めてはいけません。まして何かを消してはいけません。
- **住所は作品自身の申告で、検証していない。** 作品は他の住所も名乗れます。それで混乱するのは作品ごとの帳簿だけです。拡張のキャッシュは digest をキーにしていて、読むたびに照合しているためです。
- **住所が付くのは HTTPS で開いたエディターだけ。** `http://localhost` のプレビューやファイルから開いたエディターで作った作品には住所が付かず、共通のバケットに入ります。
- **別の配信元のエディターは、その配信元の下に住所を作る。** フォークしたエディターを別のホストで配信すると、作品の住所はそのホストの `/turbowarp-plus-projects/` になります。このリポジトリが受け持つのは、`kubohiroya.github.io` から配信されたエディターで作った作品だけです。
- **ダウンロードしたときのファイル名は住所と関係ない。** ディスク上の名前は作品のタイトルから付けます。

## 今後の使い方（計画）

ここから先はまだ決まっていません。実装されている手順もありません。

### 1. 作品を置く

作品を公開するには、その作品のマニフェストにある住所と同じパスに SB3 を置きます。

```text
66/66aa/0193f0a1-2b3c-7d4e-8f01-2233445566aa.sb3
```

- 置き場所は SB3 の中の `turboWarpPlus.uri` から決まります。別の名前を付けて置くと、作品の申告する住所と配信される住所がずれます。
- 同じ住所に新しい版を置くのは、作品の更新です。住所が変わらないので、開く人の記録とキャッシュの帳簿はそのまま続きます。
- このリポジトリに書き込めるのは持ち主だけです。公開版のエディターを使う人は誰でもここの住所を受け取りますが、ここへ置けるのは持ち主が受け入れた作品だけです。自分の作品を自分の場所で公開したい作者は、自分で住所を名乗ってください（例：自分の GitHub Pages）。

まずは、持ち主が手で（または pull request で）コミットする形から始める想定です。次のような自動化は、その後に検討します。

- Plus Editor の Git パネルから公開する
- [turbowarp-plus-editor-project-starter](https://github.com/kubohiroya/turbowarp-plus-editor-project-starter) で作った作品リポジトリのリリースから、ここへ写す

### 2. 置くときの確認（予定）

pull request の CI で、次の点を確かめる予定です。

- パスが `{2}/{4}/{uuid}.sb3` の形で、2段のディレクトリが UUID の末尾と一致している
- UUID が version 7 である
- SB3 の `turboWarpPlus.uri` が、置く場所の公開 URL と一致している
- ファイルの大きさが GitHub の上限より十分小さい。GitHub は 50 MB を超えるファイルに警告を出し、100 MB を超えるファイルは受け付けません。Git LFS に置いたファイルは GitHub Pages から配信されないので、LFS は使いません。

### 3. 一覧を作る（予定）

人が読む一覧では、住所と並べて作品のタイトルを出します（住所はわざと読めない形にしているため）。置いた SB3 からタイトルと住所を集めて、このサイトのトップに一覧のページを生成する予定です。

### 4. 消さない

一度公開した住所は、作品の名前としてほかの人の記録に残っています。置いた作品は原則として消しません。取り下げるときは、ファイルを消す前に、どう扱うか（取り下げたことを示すか、単に 404 にするか）を決めてからにします。

### 未決事項

- 公開の操作をどこに置くか（Git パネル、project-starter、手作業のどれか、またはその組み合わせ）
- 作品のライセンスと、作者以外の人の作品を受け入れるかどうか
- 住所を変えた作品（自分の公開先へ移した作品）の古い住所を、ここでどう扱うか
- リポジトリが大きくなったときの扱い。GitHub Pages のサイトは 1 GB までです。

## ライセンス

このリポジトリに置く作品のライセンスは、作品ごとに作品の側で示します。リポジトリ全体のライセンスは、作品を置き始めるときに決めます。
